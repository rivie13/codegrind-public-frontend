# publicdocs README

## Intro

This folder contains documentation for the project that was made by open source contributors. It is not intended to be viewed by users, but rather as a reference for developers.

## Architecture

When documenting your changes, you may want to add/change some repo level documentation changes
based on your contribution. For example, if you are working on a new feature, you may want to
create a new file in the `features` folder to document your changes.

To do this in a neat way, public docs will be split up by feature (e.g. `features/tower-defense`, `features/shop`, `features/chat`, `features/phaser`)
and then further split up by contribution/sub-feature (e.g. `features/tower-defense/contribution1` or `features/phaser/sub-feature1`)

## Rules

Please use markdown files (.md) to document your changes. Please try to contribute to existing docs first before creating new ones.

- When you make changes to the project, update the documentation to reflect the changes
- Add any relevant images or diagrams to your documentation
- Keep documentation updated with code changes
- The structure of publicdocs folder may change from time to time
